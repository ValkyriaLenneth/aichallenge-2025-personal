### 1. 时空域映射的数学基础

#### 1.1 空间域与时间域的转换关系

**空间域采样（CSV路径）**：
- 路径点按固定距离间隔采样：`s₀, s₁, s₂, ..., sₙ`
- 每个点包含：位置 `(x, y, z)` 和参考速度 `v_ref`
- 点间距通常为 1-2 米

**时间域预测（LSTM输出）**：
- 按固定时间间隔预测：`t₀, t₁, t₂, ..., t₅₀` (假设dt=0.1s，共5秒预测)
- 每个时刻输出速度：`v₀, v₁, v₂, ..., v₅₀`

**转换核心公式**：
```
空间距离 = ∫ v(t) dt ≈ Σ v_i × dt
```

# SAC强化学习系统开发规范文档

## 1. 项目背景与目标

### 1.1 项目目标
在Autoware自动驾驶系统中，基于预训练LSTM模型开发SAC强化学习系统，在固定路径上学习最优速度策略，实现更高的圈速表现。

### 1.2 技术路线
- **基础模型**：使用已训练的LSTM作为特征提取器
- **强化学习算法**：SAC (Soft Actor-Critic)
- **学习目标**：固定路径，优化速度控制
- **集成方式**：LSTM特征提取 + SAC决策优化

## 2. SAC-LSTM集成架构设计

### 2.1 整体架构

```
输入: 历史5秒13维特征序列 [sequence_length, 13]
     ↓
LSTM特征提取器 (参与端到端训练)
     ↓
压缩特征向量 [hidden_dim] (如256维)
     ↓
SAC决策网络 (Actor + Twin Critics)
     ↓
输出: 1维目标速度 [0, 15] m/s
```

### 2.2 核心组件

#### 2.2.1 特征提取器 (LSTM)
- **输入维度**：[batch_size, sequence_length, 13]
- **输出维度**：[batch_size, hidden_dim]
- **训练策略**：参与SAC端到端训练（不冻结参数）
- **初始化**：使用预训练LSTM权重

#### 2.2.2 Actor网络
- **输入**：LSTM输出的hidden_dim维特征向量
- **输出**：目标速度的概率分布参数 (mean, log_std)
- **初始化**：使用预训练LSTM的FC层权重
- **动作空间**：1维连续 [0, 15] m/s

#### 2.2.3 Twin Critic网络
- **输入**：特征向量 + 动作 → [hidden_dim + 1]
- **输出**：Q值标量
- **数量**：两个独立Critic + 两个Target Critic
- **初始化**：随机初始化

## 3. 强化学习环境定义

### 3.1 状态空间 (State Space)
- **原始输入**：历史5秒的13维特征序列
  - 当前速度、角速度 (2维)
  - 距离中心线距离、朝向偏差角 (2维)
  - -25~+25米路纹特征 (9维)
- **实际观测**：LSTM处理后的hidden_dim维特征向量

### 3.2 动作空间 (Action Space)
- **维度**：1维连续控制
- **范围**：[0, 15] m/s (目标速度)
- **约束**：符合Autoware系统规范
- **物理限制**：考虑加速度限制确保可达性

### 3.3 回合定义 (Episode)
- **开始条件**：赛道起点，初始速度0
- **结束条件**：
  - 完成一圈赛道（正常结束）
  - 触发终止条件（异常结束）
- **最大步数**：根据赛道长度和预期速度确定

## 4. 奖励函数设计

### 4.1 奖励函数公式

```
R_total = R_speed + R_track + R_smoothness + R_penalty
```

### 4.2 各组件定义

#### 4.2.1 速度奖励 (R_speed)
**直道奖励**：
```
if |curvature| < 0.01:  # 直道判断
    R_speed = 10.0 × (current_velocity / 15.0)
```

**弯道奖励**：
```
if |curvature| ≥ 0.01:  # 弯道判断
    optimal_speed = sqrt(lateral_acceleration_limit / |curvature|)
    optimal_speed = min(optimal_speed, 12.0)  # 弯道限速
    speed_error = |current_velocity - optimal_speed| / optimal_speed
    R_speed = 8.0 × (1.0 - speed_error)
```

#### 4.2.2 轨道保持奖励 (R_track)
```
R_track = -5.0 × (distance_from_centerline)²
```

#### 4.2.3 平滑性奖励 (R_smoothness)
```
speed_change = |current_action - last_action|
R_smoothness = -2.0 × speed_change
```

#### 4.2.4 终止条件与惩罚 (R_penalty)
**轨道偏离**：
```
if |distance_from_centerline| > 3.0:
    terminated = True
    R_penalty = -100.0
```

**速度异常（撞墙检测）**：
```
if target_speed > 1.0 and actual_velocity < 1.0 and step_count > 50:
    stall_counter += 1
    if stall_counter > 10:  # 连续10步低速
        terminated = True
        R_penalty = -100.0
```

### 4.3 时序关系说明

**正确的奖励计算时序**：
```python
# 标准RL转移：state_t → action_t → reward_t → state_t+1

def step(self, action_t):
    prev_state = self.current_state.copy()      # 保存state_t
    
    self.execute_action(action_t)               # 执行action_t
    
    current_state = self.get_current_state()    # 获得state_t+1
    
    # 基于执行action_t的结果计算reward_t
    reward_t = self.calculate_reward(prev_state, action_t, current_state)
    
    return current_state, reward_t, done
```

    state = env.reset()  # 重置到赛道起点

#### 5.2.3 SAC更新算法
```python
def sac_update(replay_buffer, batch_size):
    # === 批量采样 ===
    batch = replay_buffer.sample(batch_size)
    states, actions, rewards, next_states, dones = batch
    
    # === Critic更新 ===
    with torch.no_grad():
        # 1. Target动作采样
        next_actions, next_log_probs = actor.sample(next_states)
        
        # 2. Target Q值计算（悲观估计）
        target_q1, target_q2 = target_critic(next_states, next_actions)
        target_q = torch.min(target_q1, target_q2) - alpha * next_log_probs
        
        # 3. TD目标计算（贝尔曼方程）
        q_target = rewards + gamma * (1 - dones) * target_q
    
    # 4. 当前Q值
    current_q1, current_q2 = critic(states, actions)
    
    # 5. Critic损失与更新
    critic_loss = F.mse_loss(current_q1, q_target) + F.mse_loss(current_q2, q_target)
    update_critic(critic_loss)
    
    # === Actor更新 ===
    # 6. 重参数化采样
    new_actions, log_probs = actor.sample(states)
    
    # 7. Q值评估
    q1_new, q2_new = critic(states, new_actions)
    q_new = torch.min(q1_new, q2_new)
    
    # 8. Actor损失（最大化Q值 + 熵正则化）
    actor_loss = (alpha * log_probs - q_new).mean()
    update_actor(actor_loss)
    
    # === Target网络软更新 ===
    soft_update(target_critic, critic, tau=0.005)
    
    # === 温度系数更新（可选）===
    update_temperature_coefficient(log_probs, target_entropy)
```

## 6. 技术实现要点

### 6.1 网络架构细节

#### 6.1.1 LSTM特征提取器
```python
class LSTMFeatureExtractor(nn.Module):
    def __init__(self, input_size=13, hidden_size=256, num_layers=2):
        super().__init__()
        self.lstm = nn.LSTM(input_size, hidden_size, num_layers, 
                           batch_first=True, dropout=0.2)
    
    def forward(self, x):  # x: [batch, seq_len, 13]
        lstm_out, (h_n, c_n) = self.lstm(x)
        return h_n[-1]  # 返回最后一层的隐状态 [batch, hidden_size]
```

#### 6.1.2 SAC Actor网络
```python
class SACActorNetwork(nn.Module):
    def __init__(self, feature_dim=256, action_dim=1, hidden_dim=256):
        super().__init__()
        self.feature_extractor = LSTMFeatureExtractor()  # LSTM特征提取
        self.policy_net = nn.Sequential(
            nn.Linear(feature_dim, hidden_dim), nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim), nn.ReLU()
        )
        self.mean_head = nn.Linear(hidden_dim, action_dim)
        self.log_std_head = nn.Linear(hidden_dim, action_dim)
    
    def forward(self, sequence_input):  # sequence_input: [batch, seq_len, 13]
        features = self.feature_extractor(sequence_input)
        policy_features = self.policy_net(features)
        mean = self.mean_head(policy_features)
        log_std = torch.clamp(self.log_std_head(policy_features), -20, 2)
        return mean, log_std
```

## 9. 注意事项与最佳实践

### 9.1 关键原则
- **严格遵循RL基本原理**：(state_t, action_t, reward_t, state_t+1)时序关系
- **批量训练**：使用经验回放池批量更新，不使用单样本更新
- **端到端优化**：LSTM与SAC联合训练，不冻结预训练参数

### 9.2 常见陷阱
- **奖励时序错误**：确保reward_t反映执行action_t的结果
- **状态表示混淆**：区分原始输入序列和LSTM压缩特征
- **探索不足**：确保SAC的熵正则化机制正常工作

### 9.3 调优建议
- **先验证奖励函数**：确保奖励信号引导正确行为
- **循序渐进调参**：先调奖励权重，再调网络参数，最后调SAC超参数
- **充分训练**：SAC收敛较慢，需要足够的训练episodes

## 10. SAC 系统实施方案 (V2 - 讨论后版本)

本方案基于与开发团队的深入讨论，旨在将 `new_sac_gym_env` 节点直接改造为以SAC算法为主导的在线强化学习系统。此方案取代了早期的后台监控思路，并采纳了更简洁、更直接的动作应用机制。

### 10.1 核心架构与设计原则

1.  **端到端学习架构**:
    - **网络模型**: 采用集成的`SACActorNetwork`，其内部包含一个`LSTMFeatureExtractor`（用于特征提取）和一个策略头（Policy Head，用于决策）。
    - **权重初始化**: `LSTMFeatureExtractor`将使用预训练的`best_model.pth`进行权重初始化，并在SAC训练期间**参与端到端微调（不冻结）**。
    - **批评家网络 (`SACCriticNetwork`)**: 输入将是LSTM提取的`特征向量`和Actor输出的`动作`，维度为 `[hidden_dim + action_dim]`。

2.  **状态空间 (State Space)**:
    - 智能体的观测是完整的历史特征序列（例如，`[sequence_length=90, features=13]`）。
    - LSTM负责将这个高维时序输入压缩成一个固定维度的`特征向量`，作为决策的依据。

3.  **动作空间 (Action Space)**:
    - **核心变更**: Actor网络将输出一个**单一维度的连续动作 `action_t`**。
    - **物理意义**: `action_t` 代表智能体在当前状态下决策出的 **“立即要达到的目标巡航速度”**。
    - **动作范围**: `[0, 15] m/s`。
    - **设计原因**: 将动作定义为单一值是强化学习的标准实践，可以有效避免维度灾难，简化Critic网络的学习任务，并使信用分配更清晰。

### 10.2 动作应用机制 (简化方案)

此方案彻底取代了复杂的`time_to_space_mapping`函数。

1.  **废除时空域映射**: 不再使用`time_to_space_mapping`函数。
2.  **直接轨迹修改**:
    - 创建一个新的函数 `create_direct_trajectory` 来取代旧的 `create_hybrid_trajectory`。
    - **工作流程**:
        a. 以官方发布的完整轨迹 (`original_trajectory_msg`) 为基础。
        b. 确定车辆在轨迹上的当前位置索引 `current_idx`。
        c. 定义一个短期的**速度应用范围** (Application Horizon)，例如从 `current_idx` 向前的 `N=20` 个路径点。
        d. 在此范围内，将路径点的速度从车辆的**当前实际速度**平滑地过渡到Actor输出的目标速度 `action_t`。这可以复用或改造 `ensure_velocity_continuity` 的逻辑来实现，以保证物理可行性。
        e. 范围之外的路径点保持其原始CSV速度不变。
    - **发布**: 将修改后的完整轨迹发布到 `/planning/scenario_planning/trajectory`。

### 10.3 奖励函数与学习流程

1.  **奖励函数**:
    - 严格按照本文档第 `4` 节定义的奖励函数 (`R_total = R_speed + R_track + R_smoothness + R_penalty`) 进行实现。这为智能体学习提供了正确和丰富的信号。

2.  **主训练循环 (`planner_callback`)**:
    - `planner_callback` 将作为智能体的核心驱动循环，实现标准的 **Agent-Environment** 交互。
    - **时序逻辑**:
        i. **在 `t` 时刻**:
            - 获取状态 `s_t`。
            - Actor根据 `s_t` 决策出动作 `a_t`。
            - 通过 `create_direct_trajectory` 应用动作 `a_t` 并发布轨迹。
            - **保存 `s_t` 和 `a_t`** 以备下一步使用。
        ii. **在 `t+1` 时刻**:
            - 获取新状态 `s_{t+1}`。
            - 根据 `t` 到 `t+1` 的状态变化，计算出奖励 `r_t` 和终止信号 `done_t`。
            - 将完整的经验元组 `(s_t, a_t, r_t, s_{t+1}, done_t)` 存入 `ReplayBuffer`。
            - 如果 `ReplayBuffer` 中的数据量达到阈值，则从中采样一个 `batch`，执行一次 `sac_update` 来训练所有网络。

3.  **回合管理**:
    - **暂不实现**: 在当前开发阶段，**不实现复杂的回合重置（Reset）逻辑**。系统将连续运行和学习。

### 10.4 调试与日志

- 强化学习的调试高度依赖日志。必须在`SACLogger`中预留详尽的、结构化的日志输出。
- **关键监控指标**:
    - `Episode/Step` 摘要：`Episode: [ep], Step: [step], Total Reward: [r_total]`
