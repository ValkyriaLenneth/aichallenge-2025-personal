
# NN Planner 开发指南：从模仿到决策

本文档旨在为你提供一个清晰的、分阶段的路线图，指导你如何从一个基于专家数据的**模仿学习 (Imitation Learning)** 模型起步，并逐步升级为一个能够在新环境中**自主决策**的**强化学习 (Reinforcement Learning)** 智能体。

---

## 路线图总览

-   **第一阶段：监督学习基础 (行为克隆)**
    -   **目标**: 训练一个能精确复现专家轨迹 (`raceline.csv`) 的基线模型。
    -   **产出**: 一个可靠的、在理想条件下表现完美的NN Planner，作为RL的**优秀起点 (Warm Start)**。
-   **第二阶段：强化学习进阶 (SAC微调)**
    -   **目标**: 让模型超越模仿，学会泛化、探索和从错误中恢复。
    -   **产出**: 一个鲁棒的、能够在复杂和未知场景下自主驾驶的智能规划器。

---

## 第一阶段：构建监督学习基础模型

在这一阶段，我们的核心思想是**行为克隆 (Behavioral Cloning)**。我们不造轮子，而是先让神经网络成为一个“优秀的学生”，完美地模仿“老师傅”（即`raceline.csv`）的驾驶技术。

### 1.1 数据获取与处理：将轨迹变为数据集

这是决定模型上限的关键一步。我们需要将线性的轨迹文件，转换为可供监督学习使用的 `(输入, 标签)` 数据对。

-   **数据源**: `raceline.csv` 或其他专家驾驶数据。
-   **核心思路：滑动窗口法**
    1.  想象一个窗口在 `raceline.csv` 上滑动。在任意一个时间点 `i`：
    2.  **输入 (X)**: 窗口的**起点**，即车辆的**当前状态**。这包括：
        -   `[x_m, y_m, yaw_rad, velocity_mps]` (位置、朝向、速度)。
        -   也可以加入 `[curvature, acceleration]` 等更丰富的特征。
    3.  **标签 (Y)**: 窗口**覆盖的未来轨迹**，即模型需要预测的目标。这通常是点 `i` 之后的 `N` 个点的序列（例如，`N=20` 或 `N=50`）。
        -   每个点可以是 `[x_m, y_m, velocity_mps]`。
    4.  通过将窗口从头到尾滑动一遍，一条包含数千个点的轨迹就能生成数千个可供训练的 `(X, Y)` 数据对。

-   **数据处理流程**:
    -   **创建数据集**: 编写脚本，使用滑动窗口法遍历CSV，生成数据对。
    -   **数据划分**: 将数据集严格划分为**训练集 (70%)**、**验证集 (15%)** 和**测试集 (15%)**。验证集用于调参和选择最佳模型，测试集用于最终评估模型的泛化能力。
    -   **数据标准化**: 对所有输入和输出特征进行Z-score标准化（使其均值为0，方差为1）。这是保证神经网络稳定训练的标准做法。

### 1.2 模型训练

-   **模型架构**: 推荐使用**LSTM (长短期记忆网络)**。它天然适合处理序列数据，能够理解轨迹中的时序关系。
    -   **编码器-解码器 (Encoder-Decoder)** 结构是此处的经典选择。编码器读取当前状态(X)，解码器生成未来的轨迹序列(Y)。
-   **训练流程**:
    -   **损失函数**: 使用**均方误差 (MSE, Mean Squared Error)**，它衡量的是预测轨迹与真实轨迹之间的几何距离。
    -   **优化器**: 使用**Adam**。
    -   **核心目标**: 在训练集上训练模型，同时在每个训练周期 (Epoch) 结束时在**验证集**上评估。保存那个在验证集上损失最低的模型，以防止过拟合。

### 1.3 集成与测试

将训练好的模型（`.pth` 或 `.onnx` 文件）集成到一个ROS2节点中，替换掉原有的规划器。该节点订阅车辆当前状态，输出预测的局部轨迹。

## 第二阶段：强化学习进阶 (SAC)

当我们的模型已经能完美复现专家轨迹后，就让它“出师”，去更广阔的环境中学习真正的“驾驶智慧”。

### 2.1 核心思想：从预训练模型开始微调

我们**不从零开始训练RL**。而是加载第一阶段训练好的监督学习模型作为**初始策略**。这能带来巨大的好处：
-   **大幅缩短训练时间**: 智能体已经具备了非常好的基础驾驶能力，无需从“如何走直线”开始探索。
-   **提高训练稳定性**: 探索将在一个“靠谱”的策略周围进行，而不是完全随机的，这使得学习过程更平滑，更容易收敛。

### 2.2 SAC 算法深度解析

SAC (Soft Actor-Critic) 是一个Off-Policy算法，以其高样本效率和强大的探索能力著称。它的核心是**最大化熵的策略优化**。

**目标函数**: `J(π) = E[Σ(γ^t * (R(s_t, a_t) + α * H(π(·|s_t))))]`

-   `R`: 奖励 (Reward)
-   `α`: 熵温度系数 (控制探索的权重)
-   `H`: 策略的熵 (衡量策略的随机性/不确定性)

简单来说，SAC不仅想获得高奖励，还希望自己的策略“不确定性”尽可能大，即**在有同样高回报的动作中，选择尽可能地多样化**。这就是它探索能力和鲁棒性的来源。

### 2.3 SAC 的三大核心组件

SAC由三个（实际上是五个）神经网络组成：

1.  **一个演员 (The Actor / Policy Network)**
    -   **职责**: 决策者，即“司机”。
    -   **输入**: 状态 `s`。
    -   **输出**: 一个**随机性**的动作 `a`。它输出一个概率分布（通常是高斯分布的均值和方差），而不是一个确定的动作。
    -   **目标**: 调整自身参数，使得其输出的动作能在“评论家”那里获得尽可能高的评分。

2.  **两个评论家 (The Twin Critic / Q-Networks)**
    -   **职责**: 评估者，即两个“副驾驶”。
    -   **输入**: 状态 `s` 和一个**可能的动作** `a`。
    -   **输出**: 一个Q值，代表“在状态s下，执行动作a，未来能获得的总期望回报是多少”。
    -   **为何是两个？**: 这是为了解决Q值被**高估**的问题。在更新策略时，算法会采信两个评论家中**更悲观（Q值更小）**的那一个的评估结果，这使得学习过程更加稳定。

3.  **熵温度系数 Alpha (The Temperature)**
    -   **职责**: 动态调整“探索”与“利用”的平衡。
    -   **机制**: `α`本身也可以被自动学习和调整。
        -   如果策略表现得过于随机（熵太高），导致性能不佳，系统会自动**降低**`α`，让策略更专注于高奖励动作。
        -   如果策略过早地收敛到某个局部最优（熵太低），系统会**提高**`α`，鼓励更多的探索。

### 2.4 SAC 训练流程详解

1.  **交互**: 演员网络根据当前状态`s`，输出一个动作`a`去环境中执行。
2.  **反馈**: 环境返回奖励`r`和下一个状态`s'`。
3.  **存储**: 将这条经验 `(s, a, r, s')` 存入**经验回放池 (Replay Buffer)**。
4.  **采样**: 从回放池中随机抽取一批（minibatch）历史经验。
5.  **学习**:
    -   **更新评论家**: 使用这批数据，训练两个评论家网络。它们的目标是让自己的Q值预测，尽可能接近“真实”的Q值（即`即时奖励 + 下一状态的Q值`）。
    -   **更新演员**: 演员网络的目标是输出能让（悲观的那个）评论家给出最高Q值的动作。
    -   **更新Alpha**: 根据当前策略的熵与目标熵的差距，来调整`α`值。
6.  **循环**: 回到第一步。

### 2.6 技术核心：RL中的参数是如何更新的？(与DL的联系)

你可能会问：在深度学习中，我们通过优化器和反向传播来更新模型参数。在强化学习中，没有了“真实标签”，参数是如何更新的？

答案是：**核心机制完全相同。RL同样在PyTorch这样的框架中，通过定义损失函数（Loss Function）、反向传播（Backpropagation）和优化器（Optimizer）来更新参数。**

RL的精妙之处在于，它在算法内部为自己创造出了“伪标签”或“优化目标”。下面以SAC为例，说明演员和评论家网络是如何通过各自的损失函数来更新的。

#### 评论家网络 (Critic) 的更新

-   **目标**: 准确地预测Q值 `Q(s, a)`。
-   **Loss定义**: 它的学习过程非常像一个回归任务。我们使用**贝尔曼方程**来构建一个动态的、临时的“标签”。
    1.  **预测值**: `predicted_Q = critic(s, a)`
    2.  **目标值 (伪标签)**: `target_Q = r + γ * (Q_next - α * log_prob_next)`，即“即时奖励”+“未来期望回报”。
    3.  **损失函数**: `loss_critic = MSE(predicted_Q, target_Q)`
-   **更新**: 通过PyTorch的优化器最小化这个MSE损失，评论家就能学会更准确地评估状态和动作的价值。

#### 演员网络 (Actor) 的更新

-   **目标**: 做出能让评论家打出最高分的动作。
-   **Loss定义**: 演员没有“正确动作”作为标签。它的优化目标是**最大化**从评论家那里得到的Q值。
    1.  **演员出招**: `a = actor(s)`
    2.  **评论家打分**: `q_from_critic = critic(s, a)`
    3.  **损失函数**: 为了用只能最小化损失的优化器来**最大化**Q值，我们把损失定义为它的**负数**。
        `loss_actor = -q_from_critic` (在SAC中会额外加入熵项)
-   **更新**: 通过最小化这个负Q值，演员间接地学会了如何调整策略，以做出能够获得最高长期回报的动作。

**总结**: 你作为DL专家的知识完全可以平移。需要掌握的新技能，主要是理解和构建RL世界里那些巧妙的、用于指导网络更新的损失函数。

### 2.7 关键问题：在没有全局路径时如何定义“前进”

这是RL落地时的核心问题。我们需要将“沿着路往前开”这个模糊概念，转化为清晰的、可计算的数学目标。

-   **方法一：虚拟前置点法 (Virtual Rabbit Method) - [首选推荐]**
    -   **逻辑**: 在车辆前方一定距离（如20米）处的**车道中心线**上，动态生成一个虚拟目标点。智能体的任务就是不断追逐这个在前方引导的“兔子”。
    -   **实现**: 需要一个可靠的模块（基于视觉或激光雷达）来实时提取车道中心线。Autoware中可能已有相关模块。
    -   **整合**:
        -   **状态 (State)**: 加入“虚拟目标点在车辆坐标系下的相对位置”和“车辆朝向与目标方向的夹角”。
        -   **奖励 (Reward)**: 奖励与“到虚拟点的距离”和“朝向误差”负相关。距离越近、角度越正，得分越高。

-   **方法二：纯奖励塑形法 (Reward Shaping Method)**
    -   **逻辑**: 不创造明确目标，而是通过奖励函数直接塑造行为。如果车辆保持在“路中间且车身摆正”，就持续获得高分。
    -   **实现**: 实时计算“车辆相对车道中心的横向偏移”和“车辆朝向与车道方向的夹角”。
    -   **整合**: 对State的要求更高，必须包含能让网络理解道路结构的信息（如BEV图）。奖励函数直接与横向偏移和朝向误差负相关。

-   **方法三：成本地图法 (Costmap Method)**
    -   **逻辑**: 创建一个鸟瞰图，其中每个像素都有一个“成本”。车道中心成本为0，路沿、障碍物成本极高。智能体的目标是规划一条总成本最低的路径。
    -   **实现**: 需要一个模块来根据感知信息生成成本地图。
    -   **整合**: 将车辆周围的成本地图作为图像输入到State中。奖励函数直接与车辆当前位置的成本值负相关。

## 第三阶段：系统级优化——解决规划器与控制器的鸿沟 (Planner-Controller Gap)

一个常见且关键的问题是：Planner输出的理想轨迹，与Controller实际执行的轨迹之间永远存在**跟踪误差 (Tracking Error)**。在高速或大曲率弯道，这个误差是导致撞墙的主要原因之一。以下是从易到难的三种策略来解决这个系统级的Gap。

### 策略一：为误差预留空间 (安全走廊法)

这是最简单、最务实的工程方法。既然知道Controller会犯错，那我们就在源头上为它留出犯错的余地。

-   **核心思想**: 不再学习那条贴着墙的极限路径，而是学习一条在赛道中央、有足够安全边际的路径。
-   **具体做法**:
    1.  **准备赛道边界数据**: 获取赛道内、外墙的坐标。
    2.  **预处理`raceline.csv`**: 遍历路径上的每个点，如果该点与墙壁的距离小于一个**安全阈值**（例如0.5米），就将其向赛道中心移动，直到满足安全距离。
    3.  **使用“安全路径”训练**: 用这条新的、更保守的路径作为“完美标签”，去生成所有训练数据。
-   **效果**: 大大降低因跟踪误差导致的碰撞，显著提升系统鲁棒性。

### 策略二：让Planner“理解”并“补偿”Controller

这是更高级的、基于学习的方法，让Planner学会预判Controller的行为，并主动输出一个能“补偿”其误差的轨迹。

-   **核心思想**: 让Planner学习：“当我处于**实际状态A**时，我应该输出一个怎样的**指令轨迹B**，才能让下游的Controller最终走出那条**理想轨迹C**？”
-   **数据收集流程**:
    1.  **运行系统**: 在模拟器中，用你当前最好的Planner驾驶。
    2.  **同时记录**:
        -   **数据流A**: Planner**输出的**理想轨迹 (`/planning/scenario_planning/trajectory`)。
        -   **数据流B**: 车辆**实际执行的**轨迹 (`/localization/kinematic_state`)。
    3.  **创建新的数据集**:
        -   **输入(X)**: 某个时刻`t`的**实际车辆状态** (来自数据流B)。
        -   **标签(Y)**: 在该时刻`t`，Planner**输出的那个轨迹** (来自数据流A)。
-   **效果**: Planner学会了将Controller的动态特性建模进去，输出“预失真”的轨迹指令，从而让最终的执行效果趋近完美。

### 策略三：将误差作为输入，形成闭环决策

这是策略二的补充，让Planner的决策更具实时性。

-   **核心思想**: 让Planner实时知道自己计划的执行情况，以便动态调整。
-   **具体做法**:
    1.  **实时计算跟踪误差**: 在系统中，计算Planner输出的轨迹与车辆实际位置之间的横向和朝向误差。
    2.  **丰富输入状态**: 将这些误差作为**新的特征**，加入到Planner的输入状态`X`中。
        -   `X_new = [x, y, yaw, velocity, lateral_error, heading_error]`
    3.  使用这个增强后的状态 `X_new` 进行训练（SL或RL）。
-   **效果**: Planner能根据实时的跟踪表现做出更智能的决策。例如，当发现误差增大时，主动规划更平缓的路径以减轻Controller的负担。

### 总结与建议

| 策略 | 核心思想 | 实现难度 | 效果 |
| :--- | :--- | :--- | :--- |
| **策略一：安全走廊** | 从源头规避风险，给误差留空间 | ★☆☆☆☆ (简单) | ★★★☆☆ (显著提升鲁棒性) |
| **策略二：学习补偿** | 让Planner预判并补偿Controller的误差 | ★★★★☆ (复杂，需数据采集) | ★★★★★ (可能达到最优性能) |
| **策略三：误差作输入** | 告诉Planner当前的跟踪表现，形成闭环 | ★★★☆☆ (中等) | ★★★★☆ (提升动态调整能力) |

**行动建议**:

1.  **立即实施策略一**: 这是最快见效、投入产出比最高的方法。
2.  **并行准备策略二**: 在测试策略一的同时，开始记录数据，为训练更强的Planner做准备。
3.  **在RL阶段融合策略三**: 在强化学习的State中加入跟踪误差，让智能体学会更精细的控制。
